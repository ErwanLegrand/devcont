# devcont — Product Guidelines

## Brand

- **Name:** `devcont` (lowercase, single word).
- **Tone:** technical, terse, action-oriented. No exclamation marks, no marketing language.
- **License footer:** dual-licensed MIT OR Apache-2.0. Keep both `LICENSE-MIT` and `LICENSE-APACHE` files visible at repo root.

## CLI UX Principles

- **Subcommand-driven.** Top-level commands are verbs (`devcont`, `devcont rebuild`). New behavior should be a flag on an existing command unless it warrants a new verb.
- **Sensible defaults; explicit overrides.** A bare `devcont` should "just work" inside a project with `.devcontainer/devcontainer.json`.
- **Friendly errors, not stack traces.** User-facing errors go through `anyhow` with context; internal errors use `thiserror`. Print actionable messages; reserve traces for `RUST_BACKTRACE=1` or high verbosity.
- **Color is a courtesy.** Use `colored` for emphasis. Honor `NO_COLOR` and detect non-TTY stdout to disable.
- **Logging.** Structured via `tracing`. Default level WARN; `-v` → INFO, `-vv` → DEBUG, `-vvv` → TRACE. Logs go to stderr; stdout is for user-facing output and machine-readable data.
- **Determinism.** Identical inputs produce identical container state. No hidden cache magic; if we cache, surface where and how.
- **CI-first.** Every command must run non-interactively. Never prompt; fail fast with a clear error if input is missing.

## Documentation Style

- **README** is the user's first stop. Keep it scannable; tables for option matrices.
- **CLI help (`--help`)** is the second stop and must be accurate. Clap's derive macros generate it from doc-comments — keep doc-comments tight and in imperative mood.
- **CHANGELOG.md** is generated by `git-cliff`. Preserve conventional-commit discipline so the changelog stays accurate.
- **`docs/`** holds longer-form notes (engine-specific quirks, architecture decisions).

## Configuration Conventions

- User config lives at `~/.config/devcont/config.toml` (XDG-compliant via the `directories` crate).
- Per-project config lives in `.devcontainer/devcontainer.json`. Never invent a parallel `.devcont.toml` per project.
- Precedence: CLI flags override environment variables, which override config-file values, which override built-in defaults. Document this precedence in `--help`.

## Compatibility Promises

- The `devcontainer.json` schema we accept tracks the upstream containers.dev spec. Document supported fields in `README.md`.
- Breaking changes to the CLI surface require a minor-version bump pre-1.0 and a major-version bump after 1.0, with a deprecation notice in `CHANGELOG.md`.
- MSRV bumps are `feat` or `chore` commits with a clear note in `CHANGELOG.md` and `Cargo.toml`.
